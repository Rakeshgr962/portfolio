Flagship · Systems & HPC C11, Cache Tiling & OpenMP

Dense Matrix Multiplication

An empirical high-performance computing study of CPU cache hierarchies, loop reordering, cache blocking, and OpenMP collapse(2) parallelization.

/ Evaluates 6 C11 compute kernels with 64-byte aligned memory allocation, warmups, median filtering, and an 81-test verification suite (ε < 10-9).
/ Proves an ~12.6x speedup achieved purely through loop reordering (ikj over ijk) by converting column-strided cache thrashing into sequential spatial locality.

03 / Philosophy Engineering Approach

How I Build Software Systems

Four core principles that dictate my technical choices across machine learning, backend design, and high-performance engineering.

01 / DISCIPLINE

Problem First, Stack Second

We don't reach for distributed microservices or LLMs when a rule-based engine or PostgreSQL Row Level Security solves the problem with zero maintenance overhead. The simplest architecture that guarantees correctness is always the right one.

02 / PRODUCTION AI

ML with Real Interfaces

Jupyter notebooks are valuable for proving hypotheses, but real engineering begins when models are decoupled from research artifacts: wrapped in typed FastAPI endpoints, protected against data leakage, containerized with Docker, and tested against real inputs.

03 / HARDWARE EMPATHY

Hardware-Aware Performance

Scaling cloud compute is expensive; understanding cache hierarchies is free. As demonstrated in my matrix multiplication study, optimizing memory stride access and loop tiling delivers an ~12x speedup before spinning up a single multi-core thread.

04 / DEFENSE IN DEPTH

Database-Enforced Security

Application-level authorization checks are vulnerable to developer oversight. In multi-tenant systems like AIET-UniSphere, data boundaries are codified directly in PostgreSQL RLS policies, making authorization bypass impossible at the API tier.
