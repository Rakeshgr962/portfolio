01 / Overview

A role-aware campus academic platform engineered for Alva's Institute of Engineering and Technology (AIET). Replaces fragmented institutional portals with a unified, role-segregated environment where data isolation is enforced at the database layer via PostgreSQL Row Level Security (RLS) policies evaluated on authenticated JWT sessions.

02 / The Problem

Academic institutions frequently operate on fragmented software where students, faculty, heads of departments (HOD), and administrators require strictly partitioned views of academic records, attendance, and internal evaluations. Standard application-level RBAC is vulnerable to logic bugs in API middleware proxies, risking unauthorized data exposure.

03 / My Solution & Architecture

Built using React 19 and TypeScript with Vite on the client, paired with Supabase as the backend data layer. Rather than deploying and maintaining a fragile custom Node/Express middleware server that proxies database queries, authorization rules reside directly in PostgreSQL RLS policies evaluated on every authenticated JWT session.

Key Engineering Decisions & Trade-Offs

Database-Enforced Authorization over API Middleware

Application-level authorization checks are susceptible to developer oversights in route handlers. Embedding security rules directly in PostgreSQL RLS policies guarantees that even if a frontend query is modified, the database rejects unauthorized reads and mutations.

Role-Segregated Client Workspace Directory Structure

Separated institutional workspaces into dedicated directories (src/student, src/faculty, src/hod, src/admin). This isolates component dependencies and prevents accidental permission leaks across institutional roles.

Automated Migration Versioning & Oxlint CI

Schema mutations are codified into versioned SQL files, ensuring reproducible environments across team contributors and zero configuration drift.

05 / How It Works & Interactive Visualizer

Here is a breakdown of how the system functions in practice:

  • Four distinct institutional dashboards: Student, Faculty, HOD, and Admin.
  • Database-enforced Row Level Security (RLS) evaluated on JWT claims.
  • Attendance tracking and Continuous Internal Evaluation (CIE) record management.
  • Department-wide analytics and approval queues for department heads.
  • Responsive, carbon-conscious interface with strict accessibility standards.

06 / Results & Verified Findings

  • 100% Database-enforced authorization: Zero vulnerability to API proxy authorization bypass.
  • Multi-role segregation: Distinct, custom dashboard views for 4 institutional roles.
  • Zero custom server overhead: Reduced operational costs, deployment maintenance, and cold-start latency.

07 / What I Learned & Direct Contributions

Key engineering responsibilities and lessons gained during this project:

  • Architected the role-based directory structure (src/admin/, src/faculty/, src/hod/, src/student/) and shared services layer.
  • Implemented Supabase Auth integration with role-specific claims embedded directly into session JWTs.
  • Authored database migrations and PostgreSQL Row Level Security (RLS) policies guaranteeing that students can never mutate grade records or view peers' private evaluation metrics.
  • Configured automated CI workflows and strict Oxlint linting pipelines for code quality enforcement.

08 / Future Improvements

Advanced ML-based student risk forecasting and automated advising features remain on the architectural roadmap; current deployment focuses purely on rock-solid identity, permissions, and institutional operations.
